# MailControl M1

Первый рабочий этап: браузерный интерфейс, группы аккаунтов, черновики и
сохранение в PostgreSQL. **Письма не отправляются. Реальные почтовые пароли
не принимаются.** Это ещё не полный почтовый продукт.

## Быстрый запуск на Windows

Нужны Windows 10/11 с рабочим Docker Desktop, Linux-контейнерами и Docker Compose
версии 2.20 или новее. На первом запуске нужен интернет для загрузки образов и
зависимостей. Требования к системе — в
[инструкции Docker](https://docs.docker.com/desktop/setup/install/windows-install/).
Практический ориентир для Docker: 2 процессорных ядра и 4 ГиБ памяти, помимо ресурсов Windows.

1. Полностью распакуйте `MailControl-M1.zip` в доступную для записи папку.
   Не запускайте файлы прямо из окна архива.
2. Запустите Docker Desktop и дождитесь готовности.
3. Дважды нажмите **`START-DEMO.cmd`** в корне распакованной папки.
4. Дождитесь сборки. Браузер откроет **http://localhost:3000**.
   Если он не открылся, введите этот адрес самостоятельно.

В исходниках репозитория те же файлы находятся внутри `mailcontrol/`.
Локальный пароль БД создаётся автоматически в `mailcontrol/.env` и не нужен
для входа в интерфейс. Не публикуйте этот файл и не удаляйте его при обновлении.

- **`START-DEMO.cmd`** — явно включает примеры: 3 группы, 12 аккаунтов и 3 черновика.
- **`START-EMPTY.cmd`** — запускает пустое локальное приложение. Создайте свою
  группу и черновик; SMTP в этом режиме тоже отсутствует.
- **`STOP.cmd`** — останавливает приложение, **не удаляя данные**.

Демонстрационная и пустая локальная версии используют разные постоянные тома БД.
Одновременно через порт 3000 работает один режим. Запуск другого переключает
приложение на его отдельную БД; прежние данные остаются в своём томе.
Не выполняйте `docker compose down -v` и не удаляйте тома Docker, если хотите
сохранить группы и черновики. Обычный перезапуск не очищает базу.

**Статус проверки:** приложение проверено на Linux с PostgreSQL, в Chromium
1440×900 и 1280×853. Прошли 22 автоматические проверки, создание/редактирование
в браузере и сохранение после перезапуска API. ZIP проверен повторной сборкой
после распаковки. Инициализация БД для Docker проверена на Linux официальным
сценарием запуска образа `postgres:16` с локальным PostgreSQL 16: роль приложения
создаётся без прав суперпользователя, миграции и деморежим проходят под ней.
Сами контейнеры в Docker Desktop/Windows в этой среде не запускались. Это не
утверждение о пройденной Windows-приёмке; отдельная проверка предусмотрена в M5.

## Что можно проверить сейчас

- Открыть четыре экрана: главная, аккаунты, рассылки, события.
- Создать группу, указав название и значения лимита для будущих новых аккаунтов.
- Найти демонстрационные аккаунты, переключить группу, фильтр и страницу таблицы.
- Открыть форму импорта как макет. Ввод доступов и импорт до M2 отключены.
- Пройти мастер, сохранить название, группу, имя отправителя, тему и обычный текст.
  Добавление получателей и запуск пока недоступны; незавершённый текст можно сохранить.
- Открыть сохранённый черновик, отредактировать его и увидеть запись в событиях.
- Обновить страницу или перезапустить приложение: сохранения останутся в БД.

Статусы аккаунтов в деморежиме — примеры, а не проверка Mail. Расход квоты пока
не рассчитывается. Нулевые отправки означают отсутствие отправителя, а не
успешно завершённую рассылку. В интерфейсе нет выдуманной «доставки во Входящие».

## Если не запускается

Все команды ниже выполняются в папке `mailcontrol`:

```powershell
docker compose ps
docker compose logs --tail=80 app db
```

- Docker недоступен — откройте Docker Desktop и включите Linux-контейнеры.
- `dependency failed to start: container mailcontrol-db-1 is unhealthy`, а в
  `docker compose logs db` есть `permission denied to alter role` и
  `The bootstrap user must have the SUPERUSER attribute` — ошибка первого архива
  M1 (версия 0.1.0): его скрипт пытался снять права суперпользователя с
  bootstrap-роли, чего PostgreSQL 16 не допускает, и инициализация обрывалась.
  С версии 0.1.1 bootstrap-роль называется `mailcontrol_admin`, а приложение
  работает отдельной ограниченной ролью `mailcontrol`. Распакуйте новый архив
  поверх старого (сохранив `mailcontrol/.env`) и запустите снова. Том от
  неудачного запуска не содержит данных приложения и продолжит работать, но
  роль `mailcontrol` в нём остаётся суперпользователем. Чтобы получить
  ограниченную роль, после `STOP.cmd` удалите **только пустой** том:
  `docker volume rm mailcontrol-local-data` или `mailcontrol-demo-data`.
  Не делайте этого, если в нём уже есть сохранённые группы и черновики.
- Порт 3000 занят — остановите приложение, которое его использует. Не открывайте
  порт в локальную сеть и не отключайте проверку Host/Origin ради запуска.
- После перемещения папки не создавайте новый `.env` поверх сохранённого:
  постоянная БД помнит свой первоначальный пароль.
- Не запускайте демонстрацию на БД другого режима. Приложение намеренно откажется
  смешивать их; это не повод вручную менять маркер режима в БД.
- При недоступной БД не выводится ложное сообщение об успешном сохранении.
  Дождитесь восстановления и повторите действие. Повтор того же запроса не создаёт дубли.

Перед публикацией логов убедитесь, что в них нет личных данных. Не отправляйте
почтовые пароли, содержимое `.env` и базы получателей в чат или Git.

## Для разработки

Самостоятельный проект: Node.js 24 LTS, React, TypeScript, Vite, Fastify,
PostgreSQL 16+. Точные версии пакетов закреплены в `package-lock.json`.
Корневое приложение Hydra/Electron не требуется и не изменяется.

```sh
cd mailcontrol
npm ci
npm run typecheck
npm test
npm run build
```

API и статические файлы обслуживаются одним процессом. Для подключения БД
задайте `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`; `APP_MODE` —
`local` или явно `demo`, `PORT` по умолчанию 3000, `HOST` — `127.0.0.1`.
Затем `npm start`. Миграции применяются в транзакции при старте. Изменение уже
применённой миграции отвергается; следующие изменения БД делаются новыми файлами.

Для управляемого демонстрационного Preview в Linux:

```sh
bash mailcontrol/scripts/setup-preview.sh
bash mailcontrol/scripts/preview.sh
```

Эти скрипты создают **только свою** PostgreSQL в `mailcontrol/.local/`, на порту
55432, с уникальным локальным паролем. Основной кластер PostgreSQL не меняется.
`.local/` не входит ни в Git, ни в ZIP. Удалённый Preview принимает только
демонстрационный режим — не вносите туда реальные доступы или базы получателей.
Для внешних изменений укажите точный доверенный origin в `.local/preview-origin`;
открытый CORS и произвольные изменяющие запросы не разрешаются.

Интеграционные проверки создают отдельные временные БД и не очищают демонстрацию:

```sh
cd mailcontrol
set -a
source .local/preview.env
source .local/pg-admin.env
set +a
unset DATABASE_URL
npm run test:integration
```

Административная роль БД нужна только setup-скрипту и тестам для создания
изолированных тестовых баз. Само приложение работает без прав суперпользователя
и не может создавать базы и роли.

Сборка ZIP (для разработчика; требуется Python 3) — `npm run package` после
`npm run build`. Архив содержит исходники, lock-файл, сборку, инструкции, план
и журнал, но не `node_modules`, БД, логи и секреты. `release-manifest.json`
содержит контрольные суммы включённых файлов.

`npm run check:compose` проверяет конфигурации обоих режимов без запуска
контейнеров. Если Docker CLI отсутствует, скрипт скачивает официальный Compose
в `.local/tools/`, проверяет его контрольную сумму и не меняет системную установку.
