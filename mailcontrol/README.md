# MailControl — MVP-1

Локальная программа для рассылки обычных текстовых писем через аккаунты
Почты Mail (`mail.ru`, `inbox.ru`, `bk.ru`, `list.ru`, `internet.ru`, `xmail.ru`).
Один оператор, браузер на `localhost`, PostgreSQL как хранилище и очередь,
отдельный процесс отправки, индивидуальные скользящие лимиты у каждого ящика.

**«Принято сервисом» означает, что Mail принял письмо по SMTP. Это не доставка
во «Входящие».** Проценты доставляемости программа не выдумывает.

## Быстрый запуск на Windows

Нужны Windows 10/11, рабочий Docker Desktop с Linux-контейнерами и Compose 2.20+.
На первом запуске нужен интернет для загрузки образов и зависимостей.

1. Распакуйте архив в папку с правом записи. Не запускайте файлы из окна архива.
2. Запустите Docker Desktop и дождитесь готовности.
3. **`START-EMPTY.cmd`** — рабочий режим с пустой базой. **`START-DEMO.cmd`** —
   демонстрация с примерами (3 группы, 12 аккаунтов без паролей, 3 черновика).
4. Дождитесь сборки. Откроется **http://localhost:3000**.

Скрипт делает три шага: поднимает БД, синхронизирует пароль роли приложения
с `mailcontrol\.env`, затем собирает и запускает приложение и процесс отправки.
При сбое он сам печатает последние строки логов.

- **`STOP.cmd`** — останавливает оба режима, **не удаляя данные**.
- **`BACKUP.cmd [local|demo]`** — дамп БД и файл ключа в `mailcontrol\backups\`.
- **`RESTORE.cmd dump key [local|demo]`** — восстановление в чистое окружение
  (см. «Резервная копия»).

Каждый режим — отдельный проект Compose (`mailcontrol-local`, `mailcontrol-demo`)
со своими контейнерами и томами: `…-data` (PostgreSQL) и `…-secrets` (ключ
шифрования). Одновременно на порту 3000 работает один режим; запуск другого
останавливает первый. Не выполняйте `docker compose down -v` и не удаляйте
тома, если хотите сохранить данные.

`mailcontrol\.env` содержит только пароль локальной БД. Он создаётся сам и не
нужен для входа. При переносе папки сохраните этот файл, но даже если он
потерян, запуск пересоздаст его, а пароль роли синхронизируется с томом.

## Режимы отправки

| Режим                  | Где включается                                                        | Что делает                                                                                        |
| ---------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Тестовый отправитель   | по умолчанию; единственный в `demo` и в удалённом Preview             | письма не покидают компьютер; результат задаётся шаблонами адресов                                |
| Реальная отправка Mail | «Настройки» → «Реальная отправка через Mail», только в режиме `local` | `smtp.mail.ru:465`, TLS с проверкой сертификата, логин — полный email, пароль внешнего приложения |

Шаблоны тестового отправителя: получатели `fail-address*`/`bounce*` — адрес
не существует; `fail-temp*` — временная ошибка (повтор по настройкам);
`fail-content*`/`spam*` — отказ по содержанию (рассылка на паузу);
`unknown*`/`lost*` — ответ потерян после передачи письма (неясный исход).
Аккаунты `auth-error*`, `needs-check*`, `blocked*` исключаются с соответствующей
причиной; `temp-error*` даёт временную ошибку ящика.

Перед первой реальной рассылкой отправьте тестовое письмо (шаг «Проверка» в
мастере) на явно указанный разрешённый адрес. Это настоящая отправка с историей
и расходом квоты.

## Что делает программа

- **Аккаунты.** Импорт вставкой строк `email | app_password`, TXT или CSV
  (`email,app_password`), предпросмотр с новыми строками, дублями и ошибками,
  выбор группы и лимита `N писем / H часов` для пачки, действие для дублей
  (оставить или перенести с сохранением истории). Выгрузка ошибок без паролей.
  Массовые действия над явно выбранными аккаунтами или всем фильтром: лимит,
  перенос, отключение, включение, проверка подключения без письма.
- **Лимиты.** Скользящее окно последних `H` часов по времени БД (UTC), в
  интерфейсе — время оператора с подписью зоны. Учитываются принятые письма и
  резервы текущих отправок; смена лимита или периода не стирает историю.
- **Рассылки.** Мастер «параметры → получатели → текст → проверка», тестовая
  отправка, запуск, пауза, продолжение, окончательная остановка, исключение
  адреса из очереди, CSV-отчёт, карточка прогресса с попытками по каждой задаче.
- **Очередь.** Задачи, резервы, попытки и квоты хранятся в PostgreSQL. Процесс
  отправки регулярно подтверждает работу; два процесса не создают двойной лимит.
  После падения возвращаются только точно не начатые задачи; начатые становятся
  неясными и ждут решения оператора (подтвердить принятие, подтвердить отказ,
  закрыть без повтора).
- **Ошибки.** Неверный вход, требование проверки владельца и блокировка ящика
  исключают аккаунт с причиной и передают задачу другому ящику группы. Ошибка
  адреса завершает только задачу получателя. Отказ по содержанию ставит рассылку
  на паузу с причиной. Временные ошибки повторяются: по умолчанию до 3 повторов,
  пауза 30 мин с удвоением до 2 часов («Настройки»).
- **Доступы.** Пароли шифруются AES-256-GCM ключом из файла
  `mailcontrol.key` в отдельном томе. Ключ и пароли не попадают в API чтения,
  CSV, события и логи. Панель слушает только `127.0.0.1:3000`, изменяющие
  запросы проверяются по Host/Origin.

## Резервная копия

`BACKUP.cmd` создаёт `backups\mailcontrol-<режим>-<дата>.dump` (формат
`pg_dump -Fc`) и `…key`. **Храните оба файла вместе и не передавайте ключ:
он расшифровывает пароли аккаунтов.** Копия делается по явной команде;
допустимая потеря данных при поломке диска — всё после последней копии.

`RESTORE.cmd путь.dump путь.key [local|demo]` заменяет данные выбранного режима,
копирует ключ и применяет `docker\after-restore.sql`: выполнявшиеся рассылки
ставятся на паузу с причиной, начатые отправки помечаются неясными — после
старой копии ничего не продолжается без решения оператора.

## Если не запускается

Команды выполняются в папке `mailcontrol`; для демонстрации сначала
`set APP_MODE=demo`.

```powershell
docker compose ps
docker compose logs --tail=80 db app worker
```

- **Docker недоступен** — откройте Docker Desktop, включите Linux-контейнеры.
- **`password authentication failed for user "mailcontrol"`** — пароль в `.env`
  не совпадал с томом (например, архив распакован в новую папку). Начиная с
  версии 1.0 запуск синхронизирует пароль сам: просто запустите `START-*.cmd` ещё раз.
- **`permission denied to alter role … must have the SUPERUSER attribute`** —
  ошибка первого архива M1 (0.1.0). Новые файлы совместимы с тем томом; роль в
  нём остаётся суперпользователем, пока вы не удалите **пустой** том
  `docker volume rm mailcontrol-local-data` после `STOP.cmd`.
- **Порт 3000 занят** — остановите использующее его приложение. Не открывайте
  порт в сеть и не отключайте проверку Host/Origin.
- **Нет подтверждений процесса отправки** (главная страница) — проверьте
  `docker compose logs worker`; без работающего процесса очередь стоит.
- **Приложение отказывается открывать БД другого режима** — так и задумано;
  не меняйте маркер режима вручную.

Не отправляйте в чат или Git почтовые пароли, `.env`, файлы `*.key` и базы получателей.

## Проверенное и непроверенное

- На Linux: 8 unit и 35 интеграционных тестов на отдельных PostgreSQL-базах,
  включая гонку двух процессов за последний слот квоты, справедливую выдачу
  трём рассылкам, старого владельца резерва, границу скользящего окна, смену
  лимита и периода, замену аккаунта после ошибки входа, повторы временных
  ошибок, паузу по отказу содержания, гонки паузы/остановки/отключения/переноса
  с резервом, восстановление после падения, три решения по неясному исходу,
  поздний ответ, CSV, контролируемый SMTP-стенд для Mail-адаптера и потерю
  ответа после передачи письма. Полный список — в `PROGRESS.md`.
- Инициализация БД для Docker проверена официальным сценарием запуска образа
  `postgres:16` на локальном PostgreSQL 16, включая синхронизацию пароля с
  томами старых версий. Контейнеры в Docker Desktop/Windows в среде разработки
  не запускались — подтверждение запуска на Windows остаётся за оператором.
- Реальная отправка через `smtp.mail.ru` с настоящими аккаунтами не
  выполнялась: доступов в разработке не было. Адаптер проверен на SMTP-стенде.
- Контрольный прогон A15 (1 000 аккаунтов, 10 000 получателей, 60 минут) не
  выполнялся.

## Для разработки

Node.js 24 LTS, React 19, TypeScript, Vite, Fastify 5, PostgreSQL 16.
Версии пакетов закреплены в `package-lock.json`.

```sh
cd mailcontrol
npm ci
npm run typecheck
npm test
npm run build
```

Переменные: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`,
`APP_MODE` (`local` | `demo`), `PORT` (3000), `HOST` (`127.0.0.1`),
`MAILCONTROL_DATA_DIR` (каталог ключа), `WORKER_CONCURRENCY` (4).
API — `npm start`, процесс отправки — `node dist/server/worker.js`.
Описание маршрутов — `docs/api.md`.

Локальный PostgreSQL для разработки и тестов: `bash scripts/setup-preview-db.sh`
(порт 55432, роль приложения без прав суперпользователя, данные в `.local/`).
Интеграционные тесты:

```sh
set -a; source .local/preview.env; source .local/pg-admin.env; set +a
unset DATABASE_URL
npm run test:integration
```

`npm run check:compose` проверяет оба режима Compose без запуска контейнеров.
`npm run package` собирает ZIP после `npm run build`.
